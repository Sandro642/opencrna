# openCRNA

Simulateur de contrôle aérien **en route** (façon CRNA français), inspiré d'openScope mais centré sur
des secteurs de contrôle au lieu d'un aéroport. Premier profil : **LFBB, CRNA Sud-Ouest (Bordeaux)**.
Interface et textes en **français**. Le joueur tient une position radar : il assume les vols transférés
par les secteurs voisins, les sépare (5 NM / 1 000 ft), les amène au niveau de sortie coordonné (XFL)
et les transfère au secteur suivant.

Deux cibles construites à partir d'**un seul fichier source** :
- **Web** : `dist/openCRNA.html`, publié comme artifact claude.ai (page HTML autonome).
- **macOS** : app Electron dans `mac/` (Apple Silicon, signature ad hoc).

## Publication et mises à jour (app macOS)

Dépôt public **github.com/Sandro642/opencrna**, branche `main`. **Après chaque modification demandée
par l'utilisateur** : build + smoke test si possible, puis `./release.sh "Message en français" [patch|minor|major]`
(incrémente `mac/app/package.json`, rebuild, commit, push). Le workflow `.github/workflows/release.yml`
(runner macos-14) construit l'app et crée la release `vX.Y.Z` avec le zip et `dist/openCRNA.html`.
Le message de commit devient les « Nouveautés » affichées dans l'app : l'écrire pour l'utilisateur.
L'app (`mac/app/updater.js`) vérifie la dernière release 4 s après le lancement (et via le menu
openCRNA → Rechercher les mises à jour…), télécharge le zip, remplace le bundle et relance.
Pas de Squirrel/electron-updater : impossible sans signature Apple. Node n'est pas installé localement.
Claude Code tourne en root : toute app copiée dans /Applications doit être rendue à l'utilisateur
(`chown -R sandrombp:staff /Applications/openCRNA.app`), sinon l'updater ne peut pas la remplacer.

## Arborescence

```
src/openCRNA.src.html   Tout le jeu : CSS + HTML + JS dans un seul fichier. Contient le marqueur __GEO__.
data/geo.json           Géographie (secteurs LFBB, FIR voisines, VOR, terrains) injectée à la place de __GEO__.
data/gen_geo.py         Régénère geo.json depuis OurAirports + VATSpy (téléchargement).
data/gen_milzones.py    Ajoute à geo.json (clé milz) les zones militaires depuis l'eAIP France ENR 5.1 (édition AIRAC en argument).
build/build.py          src + geo -> dist/openCRNA.html (web) et mac/app/index.html (Electron, polices locales).
mac/app/                main.js (fenêtre, menus FR, requête OpenSky via `ipcMain.handle('opensky')`), preload.js (pont `window.opencrna.opensky`), updater.js (mises à jour GitHub), package.json (version), fonts/ (woff2 JetBrains Mono, Barlow Semi Condensed).
mac/icon.icns|png       Icône (scope radar gris).
release.sh              Incrémente la version, build, commit, push (déclenche la release).
.github/workflows/       release.yml : build macOS + release GitHub à chaque push sur main.
mac/build_mac.sh        Build + packaging Electron 33.4.11 darwin-arm64 + signature ad hoc + zip.
tests/smoke.py          Test headless Playwright : 20 min simulées avec un bot, échoue s'il y a une erreur JS.
dist/openCRNA.html      Dernière version web construite.
```

## Architecture du JS (sections `/* ===== … ===== */` dans le source)

- **Géométrie** : projection locale équirectangulaire en NM centrée 45°N / 0,9°E (`P(lat,lon)`), polygones `mkPoly`, `inPoly`.
- **Atmosphère ISA** : `casToTas`, `machToCas`, `sos` ; croisement IAS/Mach réaliste.
- **Performances** (`PERF`) : par type OACI, taux de montée interpolé selon l'altitude, plafond, IAS/Mach montée-croisière-descente, sillage.
- **Compagnies** (`AL`) : indicatifs radio, flottes, formats d'indicatif ; `fr:1` → phraséologie française.
- **Points** (`PTS`) : VOR réels + terrains + points 5 lettres **fictifs** (`FIXDEF`).
- **Unités voisines** (`UNITS`, `SECFREQ`, `APPS`) : fréquences **fictives**.
- **Configurations** (`CONFIGS`) : secteurs VATSpy LFBB (H, L, N, P, R, T, X, Z inférieurs FL115–345 ; UN, US supérieurs FL345–660 ; regroupements).
- **Militaire** : U-2 (`PERF.U2`, plafond FL700, Mach 0,62), indicatif `DRG` « Dragon », flux `mil:1` Fairford EGVA ⇄ Morón LEMO à FL610–650 (`a.mil`, symbole via `catOf`) ; exclu de `spawnConverging`. Orbites : ravitailleurs KC-135 `QID` « Quid », A330 MRTT `CTM` « Cotam » (fr), AWACS E-3 `NAT` « NATO » ; flux avec `orb:[p1,p2]` → `a.orb` (indices de route consécutifs) + `a.orbLaps` (2–4) : `stepAc` renvoie à `orb[0]` en bout d'hippodrome tant qu'il reste des tours ; `orbLaps` stocké dans les échantillons de `predict` (`ol`) et restauré par `applySample`.
- **Essais en vol** = un **poste dédié** (config `ESSAIS` : `test:1`, toute la LFBB FL100–600, fréquence 130.255, `myName` → « Bordeaux Essais ») ; sur ce poste aucun vol civil n'est concerné (`trySpawn` ne fait que du trafic de fond, `analyze` ignoré), pas de COMLOSS/convergences/coordinations, jusqu'à 3 Rafale ; sur les postes en route : ni Rafale ni zones. Section « Essais en vol » du source : **vraies zones militaires** `TZONES` lues dans `GEO.milz` (13 zones R/D : D31D, D32, D33, D300A au-dessus de l'Atlantique, R31H/B/A5 Cazaux, R34A2 Mont-de-Marsan, R49H1/H2 Cognac, R61H, R170B, R68C ; limites officielles `floor`/`ceil` en FL, 999 = UNL ; polygones `mkPoly`, point d'attente `zonePole` = point le plus éloigné des bords, marge `mg` ; `PTS[id]` de type `zone` pour DCT). Le volume du poste Essais = LFBB ∪ zones (celles de l'Atlantique débordent). Le vol d'essais orbite en cercle (rayon selon `mg`) autour du point de sa zone ; la zone demandée couvre tous les niveaux de son programme. Horaires réels non simulés : une zone reste active jusqu'à sa désactivation, états `off`→`pend` (préavis 120 s)→`on` via `toggleZone` et la page `#zonesPanel` (bouton « Zones d'essais », `renderZones`, `drawZones`). `spawnTest()` tire un type de `TEST_TYPES` (Rafale, Rafale ESA et Falcon 6X `FA6X` depuis LFBD indicatif réel Dassault Aviation **DAB** « Dassault » (téléphonie non publiée pour DAB : on reprend celle de DSO) ; Airbus A359/A21N depuis LFBO indicatif réel **AIB** « Airbus Industrie » ; `a.base`, `a.gmax`, `a.tcat` fighter/biz/liner ; programme `mkTests(cat,pf)` adapté, zones TRA exclues, marge ≥ 15 NM hors chasseur ; `PERF.RFAL` : Mach max 1,8, `acc`, `vacc`, `rod`, `bank`, `maxRate`), état `pre` jusqu'au plancher du volume puis `offered` ; `a.test`, `a.tests` (3 essais de `mkTests` : palier Mach, supersonique, virage sous G, montée FL460–500, vol lent), `testCond`, `tickTests` (progression seulement en zone active et vol assumé ; +10 par essai, +30 à l'atterrissage). Manœuvre : `cmdMan(a,g,s,dir)` (commande `MAN 5 30 D`) → `a.manG/manLeft/manDir` (nombres, pas d'objet, car `predict`/`timeToExit` clonent superficiellement). Pénalités : intrusion d'un vol sous contrôle dans une zone active −20, bang supersonique hors zone −20, zone fermée pendant les essais −10, transfert avant fin du programme −20. Le trafic de fond évite les zones actives à la création ; séparation ignorée entre le Rafale en zone active et un vol qui n'est pas à moi. Réglage `selTest` = cadence des Rafale (0 = aucun). Entraînement militaire (tous postes, réglage `selTrain`) : `spawnAiTest(true)` crée un Rafale de LFBM (indicatifs `TRAIN_CS`, `a.train`) vers une TRA (`kind:'tra'`, eAIP ENR 5.2 : TRA34A–E/N, TRA43A/W, TRA10B) ou R34A2, zone tenue par « CDC Mont-de-Marsan » (`z.ai='train'`, `z.owner`), non modifiable par le joueur. Sur les postes en route, les essais sont gérés par un contrôleur IA « Bordeaux Essais » : `spawnAiTest` (Rafale `a.ai`, trafic de fond, zone activée avec préavis 180 s, `z.ai`), `tickAiTests` (attente `aiHold`, changements de niveau dans la zone, retour LFBD, zone rendue quand plus utilisée) ; page Zones en lecture seule et seules les zones actives sont dessinées. Intrusion comptée seulement pour un vol assumé qui était hors de la zone active puis y entre, et seulement au-delà de la tolérance d'empiètement (`TOL_NM` = 2 NM latéral et 500 ft, `zoneDepth`, ou plus de 45 s dans la zone). Sortie de secteur (demande utilisateur : « je peux piétiner tant que je ne transfère pas ») : plus de transfert automatique ni de pénalité quand un vol assumé sort du volume ; il reste assumé jusqu'au transfert manuel, rappel unique dans le journal après 30 s hors secteur (`outT`, `nearVol` garde 2 NM de marge) ; la pénalité « quitte la couverture sans transfert » au retrait reste.
- **Cordo LFBB** (demande utilisateur) = poste de coordination des fréquences (config `CORDO`, `cordo:1`, `isCordo()`, `myName` → « Cordo Bordeaux ») : aucun vol à contrôler (comme Essais, `trySpawn`/`rtPlace` ne font que du fond, autres réglages désactivés). Section « Cordo LFBB » du source : `SIM.cf {fq (fréquence par secteur), broken (fin de réparation), failT, nextFail}` (`cfInit`), fréquences de secours FICTIVES `CF_SPARE`, `secAt` (secteur LFBB ≥ FL115), `cfScan` (clone + `stepAc` : `a.cE` instant d'entrée, `a.cSec`, `a.cFl`, `a.cPrev` unité précédente), `tickCordo` : demande `cfAsk` (coord `kind:'cfq'`, `pick:1`) 110–190 s avant l'entrée, `a.cIn` secteur courant, `a.cFq`/`a.cOk`/`a.cLost` ; `cmdGiveFreq` (commande `AFR123 132.555`), `cfCheck` à l'entrée (+5 ; mauvais secteur ou personne −10 et redemande ; le secteur annoncé est accepté) ; pannes `cfFail` (≤ 2 à la fois, toutes les 4–8 min, réparation 10–20 min) → coord sans avion `kind:'cfs'` (`c.a` null, `c.sec`), `cmdSecFreq` (commande globale `FQ P 131.080`, +10/+5, refus −5 si en panne ou utilisée), les vols annoncés avec l'ancienne fréquence sont redemandés. Coord `pick` : `answerCoord`/`reqMenu` ouvrent `cfMenu`. Fenêtre ATC = `cfAtcHtml` (ouverte au démarrage), radar : fréquences sur les secteurs inférieurs et supérieurs, étiquette `›UN 132.555` / `UN 132.555` (`---` rouge = injoignable).
- **Urgences 7700** : `maybeEmergency` (réglage `selEmerg`, vols assumés civils, un à la fois) → `a.emerg {kind:'dep'|'eng'|'med', ap, ack, dct, done}`, `a.sq='7700'`, terrain le plus proche de `DIV_APS`, unité suivante `divUnit` ; `dep` = descente d'urgence FL100 (`a.emRod` 6000 ft/min), `eng` = pas au-dessus du FL250 (refus dans `cmdLevel`) ; `cmdEmergAck` (commande `URG`, +5 si < 60 s, −10 sinon), un `cmdDirect` vers un terrain de `DIV_APS` en fait la destination ; bilan au transfert (+20 si pris en compte et dérouté, −15 sinon) ; `tickEmergencies` (relances du pilote).
- **Détournement 7500** : 1 urgence sur 6 de `maybeEmergency` → `startHijack` (`a.hij {real (60 %), asked, confirmed, dev, forced, done}`, `a.sq='7500'`, `a.emerg.kind='hij'` pour bloquer les autres urgences). `cmdConfirmSq` (commande `CSQ`) : erreur de sélection → code rétabli (+5) ; sinon confirmé. Réel : `tickHijacks` (déviation après 70–150 s, erre dans le volume vers son centre, n'obéit plus via `queue`), −30 si pas d'alerte en 5 min, −10 si on demande de changer le code. Alerte = `cmdAlert` (`al.hij`, +25/15/5 selon délai) ; au stade 3 autorisé, `forceLanding` → escorte vers LFBM, unité `MARSAN` (fréquence fictive), +30 à l'atterrissage. `penalty` ignore `tf`/`xfl` pour un avion détourné.
- **Transpondeur** : `a.sq` (`genSq`, 3 % de codes en double à la création), `tickSquawks` (`a.dupe`, étiquette DUPE, −5 si non corrigé ~3 min), `cmdSquawk` (commande `SQ 4521` / `SQ`), panne radio `mid` → 7600 (60 %), code d'origine rétabli à la reprise de contact.
- **Trafic réel en direct** (réglage `selTraffic` = `real`, app Mac seulement) : l'API OpenSky n'accepte pas les appels depuis la page (CORS) → `mac/app/main.js` fait la requête (`net.fetch`) et `preload.js` l'expose ; `rtAvailable()` faux dans la version web → repli sur le trafic simulé. `RT_BOX` 42–48°N / 3,5°W–5°E (2 crédits par appel, quota anonyme ≈ 400/jour, `x-rate-limit-remaining` affiché dans `#hdRt`). `mkReal(state)` : indicatif, position, altitude baro (palier arrondi au FL), vitesse, route, vario, squawk ; type déduit de la flotte `AL` (ou long-courrier via `RT_TEL`), arrivée = descente vers un terrain `LFBB_APTS` devant, route synthétique `rtRoute` (balises le long de la trace + point `SORTIE`), destination inconnue `????` → symbole `+` (`unk`). `rtPlace` = classement comme `trySpawn` (bg / pre / offered / assumed ; sur le poste Essais, toujours bg), `a.bornT` (pas de perte de séparation comptée les 90 premières secondes). `rtRefresh` toutes les 90 s : nouveaux vols, vols de fond recalés sur leur position réelle, vols disparus 2 fois retirés. En mode réel : aucun `trySpawn` ni convergence ; heure UTC réelle. Auto-test Electron : `OPENCRNA_SELFTEST=1 electron mac/app`. Codes partagés `SQ_SHARED` (1000 Mode S, 2000, 7000, 7600) jamais DUPE.
- **Flux** (`FLOWDEF`) : ~30 routes réalistes avec origines/destinations, compagnies, plage de RFL ; inverses générés automatiquement.
- **Vent** : courant-jet uniforme dont la force dépend de l'altitude.
- **Modèle avion** : `stepAc(a,dt)` (vertical avec capture, vitesse, virage taux limité par l'inclinaison de 25°, navigation avec correction de vent, séquencement des points) ; `plannedCfl` = profil plan de vol (montée RFL, descente 3:1 vers l'arrivée).
- **Prédiction** : `predict(a)` clone l'avion et simule par pas de 5 s ; `analyze(a,S)` (horizon 5400 s ; si la sortie n'est pas dans l'horizon, XFL = niveau en fin de prédiction, plafonné au plafond avion/RFL) trouve entrée/sortie du volume → `efl/eflKind`, `xfl/xflKind` (level/climb/desc), unité précédente/suivante (`unitAt`).
- **Création** : `trySpawn('c'|'b', tau)` vols concernés ou de fond, déconflictés avant l'entrée ; `adopt()` ; `maybeNordo()` ; `spawnConverging()` injecte un vol qui croise un vol pré-annoncé au même niveau dans le volume.
- **États d'un vol** : `bg` (non concerné) → `pre` (pré-annoncé, `preT`) → `offered` (transféré vers moi, `offerT`) → `assumed` → `transferred` ; `missed` si jamais pris. Annulation de transfert possible (`canRetake` : encore dans le volume ou < 90 s, pas un transfert auto).
- **Radio** : `atc()`, `pilot()`, `queue(a,delay,fn)` (réponse pilote différée ; si `a.silent` → `noResponse`).
- **COMLOSS / défense aérienne** : `a.nordo {kind:'never'|'mid', onset}`, `a.silent`, `cmdGuard` (121.5, 40 % de réussite une fois), `askAlert/cmdAlert`, `processAlerts` (étapes 0→5, 9 = terminé), chasseurs `SIM.mil` avec `stepFighter` (poursuite, supersonique, escorte, retour base). Bases `PO_BASES` (Mont-de-Marsan, Orange, Saint-Dizier), une patrouille par base (`baseBusy`), choisie dans le menu d'alerte. Alerte sur un vol en contact = `al.false` (plus de pénalité immédiate) ; `askEndAlert/cmdEndAlert` (commande `FIN`) lève l'alerte. PO sélectionnable (`selPO`, `selectPO`, `renderPO`, clic radar via `hitFighter` prioritaire, strip Défense aérienne).
- **Coordinations ATC** (`SIM.coords`, `addCoord`/`answerCoord`/`tickCoords`) : demandes en attente affichées en tête des strips avec boutons. `maybeCoord` : un voisin propose un autre niveau d'entrée (`a.coordFl`, respecté par `autoControl`) ou un cap (`a.coordHdg`) ; réglage `selCoord`. PO : `poAskInfo`/`poInfo` (infos de vol), `poAskComm` (autorisation de contacter l'équipage, sinon escorte à distance). Sans réponse : pénalité. Sens inverse : `cmdAskXfl(a,fl)` (fiche vol « Coordination sortie », commande `XFL 350`) — demande `mine:true` affichée sans boutons ; le voisin refuse si niveau non conforme au sens de vol (`semiOK`), trafic déjà à ce niveau à ±4 min de la sortie, ou au hasard selon l'écart ; accepté → `a.xfl` modifié.
- **Radio check** : `cmdRadioCheck` (commande `RC`) ; réponse « 2 sur 5 » si une panne radio `mid` est programmée. Plusieurs COMLOSS simultanés (max `ceil(nordoRate/4)`).
- **Demandes** : `reqOf(a)` = coordination non `mine` (voisin, PO) ou demande pilote `a.req` (montée/descente, posée dans `tick1s`, effacée par `cmdLevel`) → coordination de contrôleur : étiquette « REQ » clignotante + carte REQ dans `#actBar` (haut gauche du PVD, `renderAct`, boutons Accepter/Refuser ; mes demandes XFL en carte ACT) ; demande pilote : « ? » clignotant. Clic sur le champ `req` → `reqMenu`, aussi dans `acMenu` et via OK/NO.
- **Rafale : SQUAWK au lieu de l'indicatif** (demande utilisateur) : `isRafale(a)` (RFAL/RFAE) → champ `cs` de l'étiquette = `a.sq` ; chasseurs PO `drawMil` = code + altitude (`mkFighter` donne un `sq`) ; entraînement `a.train` = code + altitude.
- **PO en vol (CAP)** : réglage `selCap`, `spawnCap` (patrouille phase `cap`, orbite 9 NM à FL300 autour d'un point `CAP_PTS`), `SIM.caps`, `tickCaps` ; `airPatrols(a)` liste CAP + patrouilles engagées ; `cmdAlert(a,null,patrol)` → `reassignPatrol` (stade 2 direct, ancienne alerte close) ; bouton « Réaffecter » dans `renderPO` ; un vol en 7700 escorté n'est pas une fausse alerte.
- **PO sur alerte sur ma fréquence** (postes en route, réglage `selScr`) : `spawnScramble` crée une cible (`a.target`, avion en 7600, silencieux, souvent hors LFBB, `poOut`) et un Rafale `a.po` au départ de LFBM (`pre` → `offered` au plancher, prev `MARSAN`, `next` = unité de la cible ou MARSAN), étiquette « PO ». Contrôlé sur toute la LFBB (pas de rappel hors secteur dans LFBB), `xflOK` toujours vrai. `cmdTargetInfo` (commande `CIBLE`, +10 la 1re fois), demandes « ? » de type `info` ; JUDY à < 30 NM après infos → poursuite autonome (`a.judy`) ; interception à < 4 NM / 2 500 ft (+20 si chez moi, puis retour LFBM et transfert MARSAN). Transfert : +20 si cible hors LFBB, infos données et PO à < 25 NM de la limite (ou dehors), sinon −10 ; après transfert le PO poursuit seul (Mach 1,5 puis 0,9). Cible sortie de LFBB → `next` mis à jour. `tickScramble`. Version « badass » (demande utilisateur) : PO aux performances FICTIVES (`pf` copié de RFAL, Mach 2,6, plafond FL700 ; demande FL650 / M2,5) ; cible 7600 ou 7500 (40 %) ; après interception (`poStage` intercept → escort | order → shot → rtb) : escorte jusqu'à LFBM (cible déroutée, +15) ou, 7500 qui n'obtempère pas (50 %), engagement ordonné par la Haute autorité avec préavis 50–75 s, −20 par vol à moi à < 10 NM au tir, cible `downed` (`emRod` 16 000 ft/min, `autoControl` ignoré, étiquette ABATTU) retirée sous 800 ft (« piste perdue »).
- **Rafale ESA** : `PERF.RFAE` (démonstrateur FICTIF, Mach 2,6, plafond FL600), type `esa` fréquent (poids 4) de `TEST_TYPES`, programme Mach 2,5 au FL500 et au FL550 (+0 à 2 essais : virage sous G, montée FL570/580), zones de marge ≥ 19 NM ; commandes `M2.5` / `M250`.
- **Signalisation des essais** : étiquette `ESS fait/total` (`ESS ✓` terminé) ; `acMenu` « Programme d'essais » (zone + progression de chaque essai). Programmes de 3 à 5 essais, jusqu'à 5 vols d'essais simultanés sur le poste Essais.
- **Ligne de commande** : catalogue `CMDS` (commandes vol, filtrées selon l'état, exemple construit sur le vol via `ex(a)`) et `GCMDS` (sans indicatif : `runGlobal` — ZONE, PAUSE, X1/X2/X4, SECT, OK/NO) ; `CMD_WORD` distingue un mot de commande d'un indicatif ; autocomplétion `computeSugs`/`renderSugs` (`#cmdSug`, Tab complète, ↑↓ choisit ; après DCT points, après TRAJ indicatifs, après ZONE zones). Commandes vol ajoutées : PO, OK/NO, ROUTE, FPL, HL, VEC, TRAJ, CTR.
- **Clairances** : `cmdLevel`, `cmdHdg`, `cmdDirect`, `cmdResume`, `cmdSpeed`, `cmdAssume`, `askTransfer/cmdTransfer` (confirmation), `askRetake/cmdRetake`.
- **Boucle** : pas physique 0,5 s ; `tick1s` (états, pénalités, demandes pilotes, séparation, génération) ; balayage radar toutes les 4 s (`radarSweep`, positions affichées = `a.plot`) ; `autoLabels` place les étiquettes.
- **Séparation** : `checkSeparation` (perte < 5 NM et < 950 ft, STCA par extrapolation à 120 s) ; ne compte que si un des vols est « à moi » (`isMine`).
- **Écran radar** : canvas, `draw()`, `drawTraffic()`, `labelLines()` (champs cliquables `cs`, `cfl`, `nav`, `spd`), `drawShape()` (forme selon la destination, `destCat`), plancher/plafond au centre du volume, `drawMil()`.
- **Outils** : mesure (clic droit + glisser), **Trajectoires** (`pairAnalysis`, `avoidance`, carte `#confCard`) : croisement, CPA, verdict DANGER/ATTENTION/SÛR, résolutions en un clic.
- **UI** : fenêtres flottantes façon Aurora (voir Conventions) ; strips (Coordinations ATC / Défense aérienne / Entrants ambre / Sous contrôle vert / Transférés bleu), traffic manager **informations seulement** (demande utilisateur) : en-tête, `tmBlock` (4 colonnes DEST/I/SQK · RFL/type/TAS/`ALTN` · indicatif/téléphonie/DEP/EOBT · route + item 18) et route (plus de ligne d'état, retirée à la demande de l'utilisateur ; `tmStatus` n'est plus affichée) ; `renderPanel` construit encore l'ancienne fiche puis `pruneTM` ne garde que ces éléments — les ordres passent par le clic droit et la ligne de commande, COMBOX (journal + `runCmd`), fenêtre ATC (`renderAtc`), étiquettes : `a.hl` (Highlight), `a.showRoute`, `a.vecOn` ; touches Tab (route) et F8 (plan de vol) ; réglages en `localStorage` (`opencrna.v1`, dont `theme`).

## Conventions et choix déjà validés par l'utilisateur

- Interface **façon Aurora (IVAO)** demandée par l'utilisateur : barre de titre, MENU BAR / PREF BAR (`#navbar`, actif en gras), PVD plein écran, fenêtres flottantes déplaçables/redimensionnables (`.win` : TRAFFIC MANAGER, COMBOX, ATC — **pas de fenêtre STRIPS**, refusée par l'utilisateur ; `#strips` reste caché ; `WINDEF`, positions dans `localStorage` `opencrna.win`), menus contextuels au clic droit (`acMenu` selon l'état, `pvdMenu`, `showMenu` générique avec sous-menus « ‹ retour », `showFpl`) ; clic droit glissé = mesure. Thème **Aurora** (bleu nuit, `COL_AURORA`) par défaut, thème **Noir** (noir et gris d'origine, `COL_NOIR`) au choix dans PVD (`applyTheme`, sauvegardé). Couleurs d'état inchangées : ambre = entrants, vert = sous contrôle, bleu = transférés, rouge = alertes (STCA, perte de séparation, COMLOSS).
